---
name: dsh-superagent-github
description: Read GitHub issues, pull requests, reviews and CI using gh.
---

Stop the current Ticket before setting `execution:external`; clearing it resumes unprocessed open requests. Adopt an owned PR with `pr_number` and `pr_adoption_reason`, preserving its identity. Verify Git root and branch; never write in an occupied checkout.

Workers use orchestrator_read for repository context when needed: github/issues/<number> or github/pulls/<number> for the description; github/issues/<number>/comments/1 for conversation comments; github/pulls/<number>/comments/1 for review comments; github/pulls/<number>/thread/<comment-id> for the review thread of any of its comments; github/pulls/<number>/reviews/1 for reviews; github/pulls/<number>/checks for CI. Read github/pulls/<number>/state once when a review needs the current head, mergeability, CI counts and latest reviews together instead of four or five separate calls. Its checks and reviews may be a short-lived reuse keyed by the current head, and its `cache` field says so: that reuse never replaces the real-time `gh` check before a merge, an authorization or any other write. A page holds 20 entries and names next_resource while another may follow. A comment or review is `{ id, from, at, text, reply_to?, path?, line?, url }`: `id` is GitHub's comment id, `reply_to` the first comment of its review thread, `path` and `line` a review comment's file and line, and `bot: true` marks a bot or GitHub App, whose words never authorize work. Follow next_offset to finish the current response; offset 0 reads afresh, later offsets the same snapshot. Reading does not create tickets or send replies. Allowed mentions subscribe the issue/PR. Subscribed comments and reviews arrive without further mentions; PRs authored by the deployment's GitHub account are subscribed automatically and changed CI on subscribed PRs is delivered. Other activity is available on demand; read the CLI instructions included in this skill for gh access to context beyond these shortcuts.

Before substantial work on a new human request or review comment, call `orchestrator_ack` with its original trigger ID and a brief request-specific `text`, even within an existing ticket; the host replies once in that source thread. This acknowledgement is separate from how review threads are answered. Do not acknowledge bots or CI.

Read github/actions/runs/<run-id> for the workflow's head SHA, event, conclusion and run attempt. Follow its next_resource to github/actions/runs/<run-id>/attempts/<attempt>/jobs/<page> for bounded job and step metadata, preserving the attempt across pages. This does not retrieve raw logs or artifacts. A skipped job is not a passed execution. PR descriptions include available head/base SHAs and mergeability (null means unknown); mergeability alone does not establish repository gate compliance or business acceptance.
Checks retain available id, head_sha and details_url. Use an Actions details_url to discover the run ID when the request only names a PR; do not ask the owner to locate it. External check providers may have a different URL and are not Actions runs.

For an additional explicitly allowed repository, use github/repos/<owner>/<repo>/pulls/<number> and the same repository prefix for other resources. This provides reads only, without event subscriptions or write authority. Read github/pulls/<number>/files/1 for paginated changes; patches may be missing or truncated. Read github/commits/<full-40-character-sha>/file/<path> for full source, including AGENTS.md and CI contracts at the actual head/base. Re-read the PR head before delivering; if it changed, identify the reviewed version and do not apply old CI evidence to the new version.

Answer and resolve review threads as the Communication section says. To resolve a thread, use GitHub GraphQL `resolveReviewThread`. 

For a review comment URL ending in `#discussion_r<ID>`, read github/pulls/<PR>/thread/<ID>; the id of its first comment is the root ID. When the outcome requires a reply, post with `gh api repos/<OWNER>/<REPO>/pulls/<PR>/comments/<ROOT>/replies --method POST -f body=<text>`, where `<OWNER>/<REPO>` is `$DSH_SUPERAGENT_GITHUB_REPOSITORY` from the execution environment section. Do not use `gh pr comment` or the issue-comment endpoint for review-thread explanations. Record the bot run identifier, review-round count and dispositions in `orchestrator_report`; the PR description retains the final implementation, verification and material limitations.

The host delivers subscribed PR comments, reviews and CI directly to the bound worker. Immediately after creating or adopting a ticket PR, call `orchestrator_report` with `state: progress` and `pr_number`; do not wait for CI or handoff. Read each original trigger and acknowledge new human requests before substantial work. Worker reports still go to the orchestrator for concise source-conversation delivery.
